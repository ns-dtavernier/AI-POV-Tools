# DLP On-Demand — New VPC, Private Subnet

Deploys a Netskope DLP On-Demand (DLPoD) appliance into a **brand-new AWS VPC** with the appliance in a **private subnet**. Outbound internet access is provided by a NAT Gateway — the appliance has no inbound exposure from the internet. DLPoD is zero-touch provisioned via EC2 user-data — no SSH or manual console steps are required.

Use this template as **Stage 1** of a staged build (it creates the VPC the other templates join) when you deploy the AIG separately. The `dlp_host` and `ca_cert_pem` outputs feed directly into the AIG bootstrap secret. See [staged build workflow](../../STAGED-BUILD.md).

---

## What this deploys

| Resource | Details |
|----------|---------|
| **VPC** | New VPC with DNS support enabled |
| **Public subnet** | NAT Gateway only — no DLPoD instances here |
| **Private subnet** | DLPoD appliance lives here |
| **NAT Gateway** | Outbound internet access from the private subnet |
| **EC2 instance** | DLPoD appliance (`m5.2xlarge` default) with optional fixed private IP |
| **TLS certificates** | CA + leaf cert generated by Terraform `tls` provider — no external CA required |
| **Security group** | Port 443 restricted to `allowed_cidr_blocks`; SSH disabled by default |
| **IAM role** | Minimal instance profile — DLPoD reads bootstrap from user-data, no AWS API calls needed |

## Environment variables

Set these before running any Terraform command. Do not put them in `terraform.tfvars`.

**AWS credentials:** A configured AWS CLI profile is required. If you haven't set one up, follow the [AWS CLI configuration guide](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-quickstart.html). Terraform picks up your default profile automatically — to use a named profile, run `export AWS_PROFILE=your-profile-name` before applying.

No Netskope API credentials are needed — this template does not call the Netskope API.

**License key:** The `dlpod_licensekey` variable is marked sensitive. Pass it via environment variable rather than putting it in `terraform.tfvars`:

```bash
export TF_VAR_dlpod_licensekey="your-dlpod-license-key"
```

Or set it in `terraform.tfvars` (the file is gitignored). Either approach works.

## Quick start

```bash
cd dlpod/new-vpc-private
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars — required: persona, dns_primary
# Set dlpod_licensekey via TF_VAR_dlpod_licensekey or in terraform.tfvars

terraform init
terraform apply
```

Bootstrap completes in **5–10 minutes** after the instance launches.

## Variables reference

### Required — no working default

| Variable | Description | Example |
|----------|-------------|---------|
| `persona` | DLPoD appliance persona | `"dlp-on-demand"` or `"dspm"` |
| `dlpod_licensekey` | Netskope license key (sensitive — use `TF_VAR_dlpod_licensekey`) | — |
| `dns_primary` | Primary DNS server IP reachable from the private subnet. Use the VPC DNS resolver (`vpc_cidr` base + 2, e.g. `10.0.0.2`) or a corporate DNS server. | `"10.0.0.2"` |

### AWS

| Variable | Default | Description |
|----------|---------|-------------|
| `aws_region` | `"us-west-1"` | AWS region to deploy into |
| `availability_zone` | `"us-west-1b"` | Availability zone — must be within `aws_region` |

### Networking

| Variable | Default | Description |
|----------|---------|-------------|
| `vpc_cidr` | `"10.0.0.0/16"` | CIDR block for the new VPC |
| `public_subnet_cidr` | `"10.0.0.0/24"` | CIDR for the public subnet (NAT Gateway only) |
| `private_subnet_cidr` | `"10.0.1.0/24"` | CIDR for the private subnet where DLPoD runs |
| `dlpod_private_ip` | `"10.0.1.10"` | Fixed private IP for the DLPoD instance — must be within `private_subnet_cidr`. Set to `null` to let AWS assign automatically. This IP is embedded in the TLS certificate IP SAN. |
| `allowed_cidr_blocks` | `["10.0.0.0/16"]` | CIDRs allowed to reach the appliance on TCP 443. Restrict to the AIG subnet CIDR or the VPC CIDR. |

### EC2

| Variable | Default | Description |
|----------|---------|-------------|
| `dlpod_ami_id` | _(auto from region map)_ | AMI ID for the DLPoD 141 appliance. Auto-selected from the built-in map for: us-east-2, us-west-1, us-west-2, eu-central-1, ap-southeast-1. Set explicitly for any other region. |
| `instance_type` | `"m5.2xlarge"` | EC2 instance type |
| `key_pair_name` | _(none)_ | EC2 key pair for SSH access. Optional — omit to use AWS Systems Manager Session Manager. |

### Identity and naming

| Variable | Default | Description |
|----------|---------|-------------|
| `appliance_name` | `"dlpod-pov"` | Name tag prefix for all AWS resources. Must start with `dlpod-` to match the deployment IAM policy. |

### Bootstrap (optional)

| Variable | Default | Description |
|----------|---------|-------------|
| `dns_secondary` | `""` | Secondary DNS server IP. Leave empty to omit. |
| `system_hostname` | `""` | Appliance hostname. Leave empty to let cloud-init set it (recommended for EC2). Set to a FQDN if the AIG must connect by hostname rather than by IP. When set, `dlp_host` uses `https://<system_hostname>` and the TLS leaf cert includes the hostname as a DNS SAN. |
| `system_timezone` | `""` | IANA timezone string (e.g. `"America/Los_Angeles"`). Leave empty for UTC. |

## Outputs — what to pass to the AIG template

After `terraform apply`, retrieve the values the AIG template needs:

```bash
terraform output -raw dlp_host      # e.g. https://10.0.1.10 or https://dlpod.example.com
terraform output -raw ca_cert_pem   # CA cert PEM — pass to AIG as dlp.certificate
```

These map to AIG secret fields:

| DLPoD output | AIG bootstrap secret field |
|-------------|---------------------------|
| `dlp_host` | `dlp.host` |
| `ca_cert_pem` | `dlp.certificate` |

## All outputs

| Output | Description |
|--------|-------------|
| `instance_id` | EC2 instance ID |
| `dlpod_private_ip` | Private IP assigned to the DLPoD instance |
| `nat_public_ip` | NAT Gateway public IP — DLPoD egress address; add to network allow-lists if needed |
| `vpc_id` | VPC ID — needed if you configure VPC peering for the AIG |
| `private_subnet_id` | Private subnet ID |
| `dlp_host` | DLP host URL for the AIG bootstrap secret |
| `ca_cert_pem` | CA certificate PEM — pass to the AIG as `dlp.certificate` |

## Staged build workflow

Because this template creates its own VPC, it can only be **Stage 1** of a staged build — the Guardrails and AIG templates then join its VPC with their `existing-vpc/` variants.

```
Stage 1: dlpod/new-vpc-private/           →  vpc_id, private_subnet_id, vpc_cidr, private_subnet_cidr, dlp_host, ca_cert_pem
Stage 2: gpu-guardrails/existing-vpc/     →  in: vpc_id, subnet_id;  out: ai_guardrails_host
Stage 3: aig/existing-vpc/                →  in: vpc_id, subnet_id, guardrails_host, dlp_host, dlp_ca_cert_pem
```

A staged build is itself the fallback to the combined `ai-services-all/new-vpc-public/` stack. Within a staged build, the preferred Stage 1 is `gpu-guardrails/new-vpc-private/` with `dlpod/existing-vpc/` as Stage 2, because `dlpod/existing-vpc/` creates the Route 53 private zone the AIG needs to reach DLPoD by hostname. This template does not create DNS — if you start here, set `system_hostname` and provide resolution for it in the VPC yourself.

See [ai-services-all/README.md](../../STAGED-BUILD.md) for the full workflow.
