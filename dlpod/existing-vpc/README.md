# DLP On-Demand — Existing VPC Deployment

Deploys a Netskope DLP On-Demand (DLPoD) appliance into an existing AWS VPC with a single `terraform apply`. DLPoD is zero-touch provisioned — Terraform generates TLS certificates and delivers the full bootstrap config via EC2 user-data. No manual console steps are required.

Use this template as **Stage 2** of a staged build — the fallback when the combined `ai-services-all/new-vpc-public/` stack is not wanted and Guardrails, DLPoD, and the AIG are deployed one at a time. See [staged build workflow](#staged-build-workflow).

---

## What this deploys

| Resource | Details |
|----------|---------|
| **EC2 instance** | DLPoD appliance (`c5d.4xlarge` default) with pinned private IP and high-IOPS root volume |
| **TLS certificates** | CA + leaf cert generated by Terraform `tls` provider — no external CA required |
| **Security group** | Port 443 restricted to `allowed_inspection_cidr`; port 22 disabled by default |
| **IAM role** | Minimal instance profile — DLPoD reads bootstrap from user-data, no AWS API calls needed |
| **Route 53 private hosted zone** | Resolves `dlpod_hostname` → `dlpod_private_ip` within the VPC |

The Route 53 zone is required because the AIG connects to DLPoD via hostname (`https://dlp.aigw.internal`), not bare IP. Go's TLS stack verifies the hostname against the cert's DNS SANs — a bare-IP URL causes verification to fail even with a valid IP SAN.

## Prerequisites

- [ ] **Terraform ≥ 1.5** — [download here](https://developer.hashicorp.com/terraform/install)
- [ ] **AWS CLI profile** configured — see [Environment variables](#environment-variables) below
- [ ] **Existing VPC** with a subnet that has outbound internet access for bootstrap
- [ ] **DLPoD license key** — obtain from Netskope

## Environment variables

Set these before running any Terraform command. Do not put them in `terraform.tfvars`.

**AWS credentials:** A configured AWS CLI profile is required. If you haven't set one up, follow the [AWS CLI configuration guide](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-quickstart.html). Terraform picks up your default profile automatically — to use a named profile, run `export AWS_PROFILE=your-profile-name` before applying.

No Netskope API credentials are needed — this template does not call the Netskope API.

**License key:** The `dlpod_licensekey` variable is marked sensitive. Pass it via environment variable rather than putting it in `terraform.tfvars`:

```bash
export TF_VAR_dlpod_licensekey="your-dlpod-license-key"
```

Or set it in `terraform.tfvars` (the file is gitignored). Either approach works.

## Quick start

```bash
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars — fill in: vpc_id, subnet_id, vpc_cidr,
#   allowed_inspection_cidr, dlpod_private_ip
# Set dlpod_licensekey via TF_VAR_dlpod_licensekey or in terraform.tfvars

terraform init
terraform apply
```

Bootstrap completes in **5–10 minutes** after the instance launches. There is no Terraform readiness gate — monitor progress directly:

```bash
# DLPoD does not support SSM Session Manager. Connect via SSH from a bastion:
ssh -i your-key.pem nsadmin@<dlpod_private_ip>
sudo journalctl -u nsbootstrap -f
```

## Variables reference

### Required

| Variable | Description | Example |
|----------|-------------|---------|
| `vpc_id` | ID of the existing VPC to deploy DLPoD into | `"vpc-0123456789abcdef0"` |
| `subnet_id` | Subnet for the DLPoD instance — must have outbound internet access | `"subnet-0123456789abcdef0"` |
| `vpc_cidr` | CIDR block of the existing VPC — used to derive the VPC DNS resolver address | `"10.1.0.0/16"` |
| `allowed_inspection_cidr` | CIDR allowed to reach DLPoD on TCP 443 — set to the AIG subnet CIDR | `"10.1.0.0/24"` |
| `dlpod_private_ip` | Static IP within the subnet CIDR — embedded in the TLS cert SAN and Route 53 A record. Changing this after apply requires replacing the instance. | `"10.1.2.10"` |
| `dlpod_licensekey` | Netskope license key (sensitive — use `TF_VAR_dlpod_licensekey`) | — |

### EC2 (optional)

| Variable | Default | Description |
|----------|---------|-------------|
| `dlpod_ami_id` | _(auto from region map)_ | AMI ID for the DLPoD 141 appliance. Auto-selected for: us-east-2, us-west-1, us-west-2, eu-central-1, ap-southeast-1. Set explicitly for any other region. |
| `dlpod_instance_type` | `"c5d.4xlarge"` | EC2 instance type. Local NVMe SSD speeds up first-boot `nsbootstrap` initialisation. |
| `key_pair_name` | `""` | EC2 key pair for SSH access. DLPoD does not support SSM Session Manager — a key pair or bastion is needed for shell access. |

### Appliance (optional)

| Variable | Default | Description |
|----------|---------|-------------|
| `dlpod_hostname` | `"dlp.aigw.internal"` | TLS certificate CN, DNS SAN, and Route 53 A record name. Must match what the AIG template uses for `dlp_host`. |
| `dlpod_ssh_public_key` | `""` | SSH public key to provision for the `nsadmin` user via bootstrap. Leave empty to skip. |
| `project` | `"netskope"` | Short project identifier used in resource names and tags |
| `environment` | `"dev"` | Deployment environment tag (`dev`, `staging`, `prod`) |

## Outputs — what to pass to the AIG template

After `terraform apply`, retrieve the values the AIG template needs:

```bash
terraform output -raw dlp_host      # e.g. https://dlp.aigw.internal
terraform output -raw ca_cert_pem   # CA cert PEM — pass to AIG as dlp.certificate
```

| DLPoD output | AIG bootstrap secret field |
|-------------|---------------------------|
| `dlp_host` | `dlp.host` |
| `ca_cert_pem` | `dlp.certificate` |

---

## All outputs

| Output | Description |
|--------|-------------|
| `instance_id` | EC2 instance ID |
| `private_ip` | Assigned private IP |
| `dlp_host` | DLP host URL for the AIG bootstrap secret (`https://<dlpod_hostname>`) |
| `ca_cert_pem` | CA certificate PEM — pass to the AIG as `dlp.certificate` |
| `security_group_id` | DLPoD SG — optionally tighten ingress after AIG is deployed |
| `route53_zone_id` | Private hosted zone ID — associate additional VPCs if the AIG is in a different VPC |

## Staged build workflow

This template is **Stage 2**. Stage 1 (`gpu-guardrails/new-vpc-private/`) creates the VPC and outputs the values this template needs; Stage 3 (`aig/existing-vpc/`) consumes this template's outputs.

```
Stage 1: gpu-guardrails/new-vpc-private/  →  vpc_id, private_subnet_id, vpc_cidr, private_subnet_cidr, ai_guardrails_host
Stage 2: dlpod/existing-vpc/              →  in:  vpc_id, subnet_id, vpc_cidr, dlpod_private_ip, allowed_inspection_cidr
                                             out: dlp_host, ca_cert_pem
Stage 3: aig/existing-vpc/                →  in:  guardrails_host, dlp_host, dlp_ca_cert_pem
```

The AIG goes last because it reads its bootstrap secret once at first boot, and that secret must already contain `dlp_host` and the CA certificate this template generates.

See [ai-services-all/README.md](../../STAGED-BUILD.md) for the full workflow.

## Tear down

```bash
terraform destroy
```

All resources created by this template are removed — your VPC, subnets, and other existing networking are not touched.

## Post-deployment: tighten security group

The DLPoD SG ingress uses a CIDR rule because the AIG security group ID is unknown at deploy time. After the AIG is deployed you can optionally replace the CIDR rule with an SG reference:

```bash
AIG_SG=$(cd ../../aig/existing-vpc && terraform output -raw security_group_id)
DLPOD_SG=$(terraform output -raw security_group_id)

aws ec2 authorize-security-group-ingress \
  --group-id "$DLPOD_SG" --protocol tcp --port 443 \
  --source-group "$AIG_SG" --region YOUR_REGION

aws ec2 revoke-security-group-ingress \
  --group-id "$DLPOD_SG" --protocol tcp --port 443 \
  --cidr YOUR_INSPECTION_CIDR --region YOUR_REGION
```
