# Staged build — deploying the three components one at a time

> **Use this only if the combined `ai-services-all/new-vpc-public/` stack is not wanted.** The staged build is the fallback for customers who wish to deploy one component at a time; it involves three state files, manual hand-off of outputs between runs, and more opportunities for mistakes.

The standalone templates exist so the three appliances can be deployed **one at a time**, each as its own `terraform apply` with its own state. All three should still land in **one VPC**: the first stage uses a `new-vpc-private/` template to create the network, and the next two use `existing-vpc/` templates to join it.

## Why the order is fixed

The AIG reads its bootstrap secret **once, at first boot**. That secret carries the Guardrails endpoint (`ai_guardrails.host`) and the DLPoD endpoint plus CA certificate (`dlp.host`, `dlp.certificate`). Both values are only known after those appliances exist — the CA certificate in particular is generated by the DLPoD Terraform run. So:

```
Guardrails and DLPoD must exist  ──►  their outputs go into the AIG tfvars  ──►  AIG boots and enrolls
```

If the AIG is deployed first, its secret has no `dlp` or `ai_guardrails` block. Re-running `terraform apply` later updates the secret but the already-booted appliance will not re-read it; you would have to replace the instance (`terraform apply -replace=netskope_aig_appliance_enrollment_token.this -replace=aws_secretsmanager_secret_version.aig_bootstrap -replace=aws_instance.aig`). Guardrails alone can also be added afterwards through the AIG CLI (see [`gpu-guardrails/README.md`](gpu-guardrails/README.md) §Registering with AIGW), but deploying in order avoids both.

## Sequence

```
Stage 1: gpu-guardrails/new-vpc-private/   creates VPC, subnets, NAT, VPC endpoints, Guardrails
         └─ outputs: vpc_id, private_subnet_id, vpc_cidr, private_subnet_cidr, ai_guardrails_host

Stage 2: dlpod/existing-vpc/               joins the Stage 1 VPC; creates DLPoD, TLS chain, Route 53 zone
         ├─ inputs:  vpc_id, subnet_id, vpc_cidr, dlpod_private_ip, allowed_inspection_cidr
         └─ outputs: dlp_host, ca_cert_pem, route53_zone_id

Stage 3: aig/existing-vpc/                 joins the Stage 1 VPC; registers and boots the AIG
         └─ inputs:  vpc_id, subnet_id, allowed_cidr_blocks, appliance_host,
                     guardrails_host, dlp_host, dlp_ca_cert_pem
```

Guardrails goes first because it is the slowest to become healthy (15–35 min) and its `new-vpc-private/` template already builds the private-subnet-plus-NAT network the other two need. DLPoD's `new-vpc-private/` could create the VPC instead, but it does not create the Route 53 zone the AIG needs for hostname TLS — `dlpod/existing-vpc/` does.

## Stage 1 — Guardrails (new VPC)

```bash
cd gpu-guardrails/new-vpc-private
cp terraform.tfvars.example terraform.tfvars   # fill in aws_region, availability_zone, image_s3_bucket
terraform init && terraform apply
```

Wait for `curl http://<private_ip>:8080/ping` → `{"status":"Healthy"}` (via SSM or a bastion), then collect:

```bash
terraform output -raw vpc_id
terraform output -raw private_subnet_id
terraform output -raw vpc_cidr              # e.g. 10.0.0.0/16
terraform output -raw private_subnet_cidr   # e.g. 10.0.2.0/24
terraform output -raw ai_guardrails_host    # http://10.0.2.x:8080/invocations
```

## Stage 2 — DLPoD (existing VPC)

```bash
cd ../../dlpod/existing-vpc
cp terraform.tfvars.example terraform.tfvars
export TF_VAR_dlpod_licensekey="<license>"
```

Set in `terraform.tfvars`:

| Variable | From |
|----------|------|
| `vpc_id` | Stage 1 `vpc_id` |
| `subnet_id` | Stage 1 `private_subnet_id` |
| `vpc_cidr` | Stage 1 `vpc_cidr` |
| `dlpod_private_ip` | A free address in Stage 1 `private_subnet_cidr` (AWS reserves the first four and the last; the Guardrails instance already holds one) |
| `allowed_inspection_cidr` | Stage 1 `private_subnet_cidr` — the AIG will sit in the same subnet |

`terraform init && terraform apply`, confirm bootstrap finished ([`dlpod/README.md`](dlpod/README.md) §Checking it worked), then collect:

```bash
terraform output -raw dlp_host       # https://dlp.aigw.internal
terraform output -raw ca_cert_pem    # -----BEGIN CERTIFICATE----- ... (public cert, safe to paste)
```

## Stage 3 — AIG (existing VPC)

```bash
cd ../../aig/existing-vpc
cp terraform.tfvars.example terraform.tfvars
export NETSKOPE_SERVER_URL="https://<tenant>.goskope.com/api/v2"
export NETSKOPE_API_KEY="<token>"
```

Set in `terraform.tfvars`:

| Variable | From |
|----------|------|
| `vpc_id` | Stage 1 `vpc_id` |
| `subnet_id` | Stage 1 `private_subnet_id` |
| `allowed_cidr_blocks` | CIDRs of the clients that will proxy through the AIG (plus `vpc_cidr` if testing from inside) |
| `appliance_host` | The private IP you expect the AIG to receive — this template does not pin one. If `aig_private_ip` in the outputs differs after apply, update `appliance_host` and apply again; it is display-only in the tenant and does not affect enrollment |
| `guardrails_host` | Stage 1 `ai_guardrails_host` |
| `dlp_host` | Stage 2 `dlp_host` |
| `dlp_ca_cert_pem` | Stage 2 `ca_cert_pem` (multi-line heredoc, or `dlp_ca_cert_pem = file("dlpod-ca.pem")`) |

`dlp_host` and `dlp_ca_cert_pem` must be set together. All three integration variables are optional — leave them empty to deploy an AIG without that integration.

`terraform init && terraform apply`, then confirm the appliance shows **connected** in the tenant ([`aig/README.md`](aig/README.md) §Verifying enrollment).

## Notes

- The AIG in `aig/existing-vpc/` gets no public IP. Clients reach it over VPN, peering, or from inside the VPC. If the POV needs an **internet-reachable** AIG together with Guardrails and DLPoD, use the combined [`ai-services-all/new-vpc-public/`](ai-services-all/new-vpc-public/README.md) stack — there is no staged path to a public AIG, because `aig/new-vpc-public/` creates its own VPC and would have to run first, before the endpoints it needs exist.
- Security groups: Guardrails `allowed_service_cidr` (default `10.0.0.0/8`) and DLPoD `allowed_inspection_cidr` must include the AIG's subnet.
- The AIG reaches DLPoD by hostname (`dlp.aigw.internal`) and verifies the TLS SAN; `dlpod/existing-vpc/` creates the Route 53 private zone. If the AIG ends up in a different VPC, associate the zone with it (`route53_zone_id` output).
- Each stage has its own state file. Keep all three; `terraform destroy` needs them.
- Tear down in reverse: AIG → DLPoD → Guardrails (Guardrails last because its stack owns the VPC).
