# AI Services — New VPC (AIG + Guardrails + DLPoD)

Deploys a complete Netskope AI Services stack in a new AWS VPC with a single `terraform apply`. All three appliances are zero-touch provisioned — no manual registration steps required.

**Use this template when** you are starting from scratch in a new AWS environment and want the full AIG + Guardrails + DLPoD stack running as quickly as possible. It creates all networking, IAM, and instance resources and wires the three services together automatically.

---

## How it works

Terraform provisions all AWS resources and the Netskope appliance registration in a defined order, enforced by readiness gates:

1. VPC, subnets, NAT gateway, VPC endpoints, and Route 53 are created first
2. Guardrails and DLPoD EC2 instances boot and run their setup sequences
3. `terraform apply` blocks at a readiness gate for each — Guardrails (~30 min) then DLPoD (~5–10 min)
4. Once both are confirmed healthy, the AIG instance is created and self-enrolls using a bootstrap secret from Secrets Manager

No SSH access is needed at any point. All instance access is via SSM Session Manager.

### EC2 instances

| Instance | Default type | vCPU | RAM | Purpose |
|----------|-------------|------|-----|---------|
| AI Gateway | `c6a.4xlarge` | 16 | 32 GB | SSL offload, policy enforcement, routes traffic to Guardrails and DLPoD |
| Guardrails | `g4dn.xlarge` | 4 | 16 GB | NVIDIA T4 GPU — LLM model inference for AI content inspection |
| DLPoD | `c5d.4xlarge` | 16 | 32 GB | DLP content scanning. Local NVMe SSD speeds up first-boot `nsbootstrap` init |
| Bastion | `t3.small` | 2 | 2 GB | SSH/SSM troubleshooting access — not needed once the POV is working (see Component roles) |

### Component roles

| Component | Subnet | Purpose |
|-----------|--------|---------|
| AI Gateway | Public | SSL termination, policy enforcement, routes AI traffic to Guardrails and DLP traffic to DLPoD |
| AI Guardrails | Private | GPU-backed LLM inference — scans AI prompts and responses against Netskope policies |
| DLP On-Demand | Private | AI-aware DLP inspection — detects sensitive data in AI queries and responses |
| Bastion | Public | Troubleshooting access only. To remove it but keep everything else, delete `bastion.tf` and run `terraform apply`; `terraform destroy` removes it along with the rest. |

### AWS resources created

| Service | Resources |
|---------|-----------|
| **VPC** | VPC, public + private subnets, internet gateway, NAT gateway, route tables |
| **EC2** | 4 instances (AIG, Guardrails, DLPoD, Bastion), 2 Elastic IPs (AIG + NAT GW) |
| **Security groups** | One per instance with least-privilege ingress/egress rules |
| **IAM** | Instance roles and profiles for AIG and Guardrails; DLPoD reads config from user-data only |
| **Secrets Manager** | AIG bootstrap secret (enrollment token + Guardrails host + DLPoD TLS config) |
| **SSM Parameter Store** | Guardrails readiness signal (`/<prefix>/guardrails-ready`) |
| **CloudWatch Logs** | Guardrails service log group (30-day retention) |
| **VPC Endpoints** | Interface: SSM, SSMMessages, EC2Messages, CloudWatch Logs. Gateway: S3 |
| **Route 53** | Private hosted zone resolving `dlp.aigw.internal` → DLPoD private IP |
| **TLS certificates** | CA + leaf cert for DLPoD — generated by Terraform `tls` provider, no external CA required |

## How long does deployment take?

`terraform apply` blocks at two readiness gates before creating the AIG. Observed timings on `g4dn.xlarge` in us-west-1:

| Stage | Duration | What's happening |
|-------|----------|-----------------|
| VPC + networking | ~2 min | Subnets, IGW, NAT gateway, route tables, VPC endpoints, Route 53 |
| Guardrails Phase 1 | ~15 min | OS package updates, NVIDIA GPU driver install, reboot to activate kernel module |
| Guardrails Phase 2 | ~15–20 min | NVIDIA container toolkit, Docker CE, 15 GB S3 image download (~130 MiB/s), `docker load`, health check |
| DLPoD bootstrap | ~5–10 min | `nsbootstrap` applies TLS certs and license key, `nssetupdlpaas` installs DLP pod |
| AIG creation | ~2–3 min | Enrollment token written to Secrets Manager, AIG EC2 boots and self-enrolls with Netskope tenant |
| **Total** | **~35–50 min** | |

## Prerequisites

Tick every box before you start. `../../scripts/preflight.sh ai-services-all/new-vpc-public` checks most of them for you.

- [ ] **Terraform ≥ 1.5** — [download here](https://developer.hashicorp.com/terraform/install)
- [ ] **AWS CLI profile** configured and pointing at the right account — see [Environment variables](#environment-variables) below
- [ ] **GPU instance quota** — "Running On-Demand G and VT instances" ≥ 4 vCPUs in your target region. AWS console → Service Quotas → Amazon EC2. Default is 0; a request can take a day.
- [ ] **Netskope REST API v2 token** and your tenant URL — Netskope tenant → Settings → Tools → REST API v2
- [ ] **AIG AMI ID for your region** — subscribe to the Netskope AI Gateway on AWS Marketplace; the ID is shown after accepting terms and is different in every region
- [ ] **DLPoD AMI ID for your region** — obtain from Netskope. The default in the template is for **us-west-1 only**; in any other region you must supply your own
- [ ] **DLPoD license key** — obtain from Netskope
- [ ] **Guardrails image in S3** — upload `aisecurity-llm.tgz` (from Netskope) to an S3 bucket **in the same region** before running `terraform apply`
- [ ] *(optional)* **EC2 key pairs** — only if you want SSH to the instances. Not needed: all access works through SSM Session Manager. If you do want them, they must already exist in the region: `aws ec2 describe-key-pairs --region YOUR_REGION`

## Environment variables

Set these before running any Terraform command. Do not put them in `terraform.tfvars`.

```bash
export NETSKOPE_SERVER_URL="https://mycompany.goskope.com/api/v2"
export NETSKOPE_API_KEY="your-rest-api-v2-token"
```

**AWS credentials:** A configured AWS CLI profile is required. If you haven't set one up, follow the [AWS CLI configuration guide](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-quickstart.html). Terraform picks up your default profile automatically — to use a named profile, run `export AWS_PROFILE=your-profile-name` before applying.

**DLPoD license key:** The `dlpod_licensekey` variable is marked sensitive. Pass it via environment variable rather than putting it in `terraform.tfvars`:

```bash
export TF_VAR_dlpod_licensekey="your-dlpod-license-key"
```

Or set it in `terraform.tfvars` (the file is gitignored). Either approach works.

## Quick start

```bash
# 1. Upload the Guardrails image to S3 (same region as the deployment)
aws s3 cp aisecurity-llm.tgz s3://my-guardrails-bucket/aisecurity-llm.tgz

# 2. Set your secrets as environment variables (see above)
export NETSKOPE_SERVER_URL="https://mycompany.goskope.com/api/v2"
export NETSKOPE_API_KEY="..."
export TF_VAR_dlpod_licensekey="..."

# 3. Copy the example variables file and fill in the four required values:
#    availability_zone, aig_ami_id, image_s3_bucket, dlpod_ami_id (unless us-west-1)
cp terraform.tfvars.example terraform.tfvars

# 4. Deploy. 'plan' only shows what will happen; 'apply' waits for you to type yes.
terraform init
terraform plan
terraform apply        # 35–50 minutes — do not interrupt
```

## Remote state

Terraform state for this template contains TLS private keys (the DLPoD CA and leaf certificate) in plaintext. Use S3 remote state with encryption at rest.

```bash
cp backend.hcl.example backend.hcl
# Edit backend.hcl — fill in your S3 bucket, region, and KMS key
terraform init -backend-config=backend.hcl
```

See [docs/deployment.md](docs/deployment.md) for the full backend configuration and why encryption matters here.

## First test — proving the POV works

Once `terraform apply` finishes and the appliance shows **connected** in the tenant:

1. In the Netskope tenant go to **Settings → Security Cloud Platform → AI Gateways** and select your appliance.
2. Add the AI providers the customer uses (OpenAI, Anthropic, etc.).
3. Point a test client at the gateway: `https://<aig_public_ip>` on port 443, where `aig_public_ip` is the `terraform output` value. The client's source IP must be within `allowed_cidr_blocks` (default `0.0.0.0/0`).
4. Send a prompt. It should appear in the tenant's AI Gateway activity, with Guardrails and DLP verdicts attached.

Guardrails and DLPoD need no separate configuration — the AIG was told about both at boot. If a verdict is missing, see [docs/troubleshooting.md](docs/troubleshooting.md) §"DLPoD not reachable from AIG" and §"Guardrails health check failing".

> Client-side proxy or SDK configuration (environment variables, base-URL overrides, certificate trust) depends on the client and is not covered here. Ask your Netskope SE for the steps for your tools.

## Rebuild reference

Use `-replace` (Terraform ≥ 1.5) rather than `terraform taint`:

```bash
# AIG only — new token + new instance
terraform apply \
  -replace=netskope_aig_appliance_enrollment_token.this \
  -replace=aws_secretsmanager_secret_version.aig_bootstrap \
  -replace=aws_instance.aig

# Full AIG re-registration — new appliance record + token + instance
terraform apply \
  -replace=netskope_aig_appliance.this \
  -replace=netskope_aig_appliance_enrollment_token.this \
  -replace=aws_secretsmanager_secret_version.aig_bootstrap \
  -replace=aws_instance.aig
```

See [docs/troubleshooting.md](docs/troubleshooting.md) for DLPoD and Guardrails rebuild procedures.

## Tear down

```bash
terraform destroy
```

Type `yes` when prompted. All AWS and Netskope resources created by this template are removed. The bastion instance is included — there is no need to remove `bastion.tf` before destroying.
